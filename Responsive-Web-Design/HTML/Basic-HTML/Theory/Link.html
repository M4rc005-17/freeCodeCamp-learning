Abbiamo visto l'attributo "target" sugli elementi ancora ("a") o sui "link". Questo attributo dice al browser dove aprire l'URL nell'elemento "a". Visit freeCodeCamp Ci sono 4 valori importanti che sono possibili per questo attributo. Ogni valore è preceduto da un trattino basso. Il primo valore è "_self" che è il valore di default. Apre il link nella stessa pagina del browser. Il secondo valore è "_blank", apre il link in un nuovo tab del browser. Il terzo valore è "_parent" che apre il link nel parente del contesto attuale. Per esempio, se il tuo sito web ha un "iframe" un valore "_parent" all'interno dell'"iframe" lo aprirà nella tab del tuo sito web e non nel frame embedded. Il quarto valore è "_top" che apre il link nel contesto di navigazione più alto. Questo è simile a "_parent", ma il collegamento si aprirà sempre nella scheda completa del browser, anche per frame incorporati annidati. Esiste un quinti valore chiamato "_unfencedTop", attualmente usato per FencedFrame API sperimentali. Selezionare il valore corretto del "target" controlla dove l'utente va a finire ed è una cosa importante da tenere in considerazione quando si crea un sito web. Un percorso è un stringa che specifica la locazione di un file o di una directory in un file system. Nello sviluppo web, i percorsi permettono ai programmatori di linkare risorse come immagine, fogli di stile, codici e altre pagine web. Ci sono percorsi assoluti e relativi, entrambi sono essenziali quando si specifica la posizione di un file all'interno di un file system. Un percorso assoluto è un link completo ad una risorsa. inizia dalla cartella root, include tutte le altre cartelle e infine il nome del file e l'estensione. Se stai linkando risorse sulla tua macchina locale, usa un percorso assoluto, che include la directory completa del file

Usa un percorso assoluto quando vuoi fare riferimento ad una risorsa che è in una posizione ben precisa. Usa un URL assoluto quando vuoi linkare delle risorse che sono su un sito web esterno. Usa un percorso relativo quando stai linkando risorso all'interno dello stesso sito web. Usa un percorso relativo se vuoi mantenere il tuo codice pulito e più facile da mantenere durante lo sviluppo. Usa un percorso relativo durante i test locali per assicurarti che i link funzionino senza una connessione ad internet. Potresti aver visto link come "/public/logo.png", "./script.js" oppure "../styles.css" nel tempo. Queste si chiamano percorsi file. Ci sono 3 sintassi importanti da sapere. La prima è la barra, che può essere "\" oppure "/" in base a che sistema operativo tu stia usando. Il secondo è il punto ".". Ed infine abbiamo i doppi punti "..". La barra, conosciuta come "separatore di percorso". Viene usata per indicare una pausa nel testo tra cartelle o nomi di file. Questo è il modo in cui il tuo computer sa che "naomis-files/" punta ad una cartella con lo stesso nome, mentre "naomis/files/" punta alla cartella "files" dentro la cartella "naomis". Un punto singolo punta alla cartella attuale, i due punti invece puntano alla cartella padre. Tipicamente vedrai il punto singolo usato per assicurarsi che il percorso sia riconosciuto come un percorso relativo. I doppi punti invece sono molto comunemente usati per accedere a file al di fuori della cartella attuale. Se il tuo file "public/index.html" ha bisogno di caricare il file "favicon.ico", useresti un percorso relativo con un singolo punto per accedere alla cartella corrente: "./favicon.ico". Se il tuo file "public/index.html" avesse bisogno di caricare il file "index.css", useresti un percorso relativo con i doppi punti per arrivare alla prima cartella padre "my-app", poi alla cartella "src" ed infine arrivare al tuo file: "../src/index.css"
